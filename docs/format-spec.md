# 频谱图格式规范（spectrum image format）

> 本文件是**契约**：v4 为首个公开发布的版本，自发布起字段文法冻结。
> 只增不改、永不重排，用户今天创建的图片，在未来任何版本里仍能读出。

## 总览

一张频谱图 = 一个普通图片容器 + 两处元数据。任何一处理论上丢了，另一处还能兜底：

| 载体 | 内容 | 丢失后果 |
| --- | --- | --- |
| PNG tEXt（keyword `spectrum`） | 完整参数数组（权威来源） | 退回文件名 |
| 文件名文法 | 参数的压缩版 | 退回通用读取（整图当幅度） |
| 像素本身 | 幅度谱（+ 相位段，若可逆） | — |

容器：PNG（8 位索引色）为权威格式，近乎无损、零爆音。
JPEG/WebP 有损重编码不损坏格式：只平滑漂移相位，读取端自动优雅降级。

> **位深只到 8**：8 位索引色的 96 dB 动态范围已覆盖 16 位音频源的全部动态，
> 更高位深只有更大的图、没有更好的声音。16 位灰度 PNG 曾是开发期档位，
> 从未随发布版本对外产出，读端不兼容（遇到按普通图处理）。

## 元数据数组（tEXt / 文件名兜底）

JSON 数组，**第 1 个元素是版本号**：

```
[版本, sr, win, hop, frames, bins, samples, bits, ref, exact]
```

| # | 字段 | 含义 | 约束 |
| --- | --- | --- | --- |
| 0 | 版本 | 整数，当前 4 | 见兼容规则 |
| 1 | sr | 采样率 Hz | > 0 |
| 2 | win | FFT 窗长，2 的幂 | 256..4096 |
| 3 | hop | 帧跳距 | 1..win |
| 4 | frames | 帧数（图宽） | > 0，≤ 20000 |
| 5 | bins | 行数 = 频点数 | ≤ win/2+1 |
| 6 | samples | 原始样本数 | ≥ 0 |
| 7 | bits | 幅度位深；0 = 可逆链路 | 0/2/4/8 |
| 8 | ref | 0 dB 参考电平（dBFS），保留 1 位小数 | 有限数 |
| 9 | exact | 1 = 携带相位（两段布局） | 0/1 |

### 兼容规则（实现必须遵守）

1. **版本严格匹配**：读端只认 `版本 == 4`，其余版本明确拒绝，走通用读取路径。
2. **未来加字段只能追加到末尾**；发布后若追加字段，读端按前缀解析、忽略扩展；
   改动已有字段语义必须升版本号，且新版本读端须显式处理旧版本。
3. **文件名文法同样冻结**：`_SR{sr}_N{win}_H{hop}_F{frames}_L{samples}_B{bits}.png`
   （B0 = 可逆）。tEXt 丢失时按此文法兜底。

## 像素布局

### 紧凑（bits > 0，单段）

图就是频谱图本身：一像素 = 一帧 × 一频点，只有幅度，颜色为暖色 ramp 的索引色。

### 可逆（bits = 0，两段，图高 = 2 × bins）

```
┌──────────────┐ 0..bins      幅度谱：G 通道 = 层级（0..255，暖色 ramp 便于观看）
│   幅度谱      │              刻度：-120 dB .. 0 dB 线性映射到 0..255
├──────────────┤ bins..2bins  相位：R = cos(φ)、G = sin(φ)（0..255，(·*0.5+0.5)*255）
│   相位        │
└──────────────┘
```

相位存 cos/sin 而非折叠角：在 2π 处连续，有损重编码只平滑漂移、不爆尖刺。

## 还原链路与质量分档

| 图的状态 | 还原方式 |
| --- | --- |
| 可逆图（相位段在，无论容器有损与否） | **直接逆变换**。实测（JPEG q=12/24 模拟）相关 0.983/0.988，优于各迭代重建（GL 精修 0.960/0.975、RTISI 暖启动 0.776/0.828）；存下的相位本身就是最优估计 |
| 紧凑图 / 相位彻底丢失 | PGHI 一次成型 + RTISI-LA 逐帧反演（快速档：8 迭代）；「精修」按钮给足算力（16 迭代 + 更大前瞻预算 + Nesterov GL 打磨），零爆音 |
| 陌生图 / 完全降级 | 整图当幅度，同上 |

「重建相位」按钮对**无相位**与**弱相位**（可靠度低于强保留阈值、但高于锚定下限且缩放不过狠）的图出现。无相位走精修迭代；弱相位把存储相位当逐 bin 加权的先验锚参与每轮迭代（锚定 GL），不当真值。相位完好的图不出按钮：直逆已最优，迭代反而有害（实测结论，勿再"优化"回去）。

## 条码票根（stub barcode，2026-09-09 增补）

导出图最底部 8px 高的黑白游程码：**meta 被剥、文件名被改、图被缩放后，恢复
采样率 / 窗长 / 原始宽度的权威通道**。游程边沿随缩放等比移动，解码用「前导四游程
总长估比例尺」，等比缩放不破坏解码；大块黑白对 JPEG 重压缩稳健。

位流（可变长，MSB first）：

```
前导 4bit (1010) · magic 4bit (1011) · 宽度前缀 2bit (0/1/2 = 8/12/16bit)
· 原始宽度 8/12/16bit · 采样率表索引 4bit · 窗长档 2bit (256/512/1024/2048)
· 可逆布局 1bit · CRC8 8bit（初值 0xFF，多项式 0x07，覆盖 magic..exact）
```

- 物理编码：每 bit 占 4px（宽 ≥160px）/ 2px（≥70px）/ 1px 竖条（1=浅 230、0=深 20），
  连续同值合并为游程；左侧 2px 深色锚；条底色深；图够宽（≥2×span+6）时写两遍。
- 采样率表：8000, 11025, 12000, 16000, 22050, 24000, 32000, 44100, 48000,
  64000, 88200, 96000, 176400, 192000（索引 14/15 保留）。
- 解码：底部行带从 8 行起逐级递减取平均亮度剖面 → 游程分解 → 找连续 4 个均匀
  交替游程（前导 1010）估单位宽 → 收位 → 校 magic/CRC。
- 图宽写不下票根时导出端不画，读端回退几何猜测。

读端语义：票根命中即剔除票根行；**meta 缺失或图被缩放过（宽 < 票根声明宽 × 0.95）
时，票根参数压过一切推断**（meta 的「时长不变」重推只考虑竖向缩放，等比缩放下
会把帧数推成宽度的数倍，比不用还糟），幅度刻度 ref 仍从 meta 继承（若在）。

## 无 meta 认图（鲁棒性兜底，2026-09-09 增补）

meta（tEXt + 文件名）都可能被压缩软件剥掉或篡改。读端按以下顺序兜底，全部命中才算「认出」：

1. **索引色 PNG 调色板签名** → PLTE 与暖色 ramp 逐项一致（G 通道 = 层级）才认，任意照片不撞签名。
2. **条码票根** → 见上节；命中即获权威参数，不再猜测。
3. **像素签名（可逆图）** → 两条律都要过（各自采样点命中率 ≥55%）：
   上半段电平像素满足 `(R,G,B) ≈ (RAMP[3G], G, RAMP[3G+2])`（逐通道容差 32）；
   下半段相位像素满足 B≤48 且 (R,G) 落在以 (127.5,127.5) 为圆心的圆环（半径 **96..160**）上。
   两条律都是统计式判定，为的是吃掉 JPEG 的 B 通道 ringing 与缩放造成的矢量塌缩；
   缩放后的图高度通常不再是偶数，故允许奇数。

   环的**上界 160 是关键**：纯黑图的电平像素能过电平律（`RAMP[0] = (0,0,0)`，黑像素逐通道自洽），
   只有相位半径挡得住它 —— (0,0,0) 到圆心 ≈180，落在环外。下界 96 则兜住 JPEG 混叠把相位半径
   **往内**拉。

认出后按几何反推参数：win = 2×(bins−1) 收敛到 2 的幂（≤4096），hop = win/2，
sr 按 8k（工具默认，无从得知，界面提示「按默认解读」）。

## 相位可靠性（分级信任，2026-09-09 修订）

读相位段时计算「平均矢量长度比」（0..1）：1:1 完整图 ≈ 1.00，缩放 0.5× ≈ 0.3-0.4
（相邻帧/频点相位矢量相互抵消），JPEG q0.72 ≈ 0.63（色度 4:2:0 下采样平均掉一半矢量，
但**方向大体还在**）。阈值取 **0.5**（`READ_TUNE.phaseReliable`）：

- ≥ 0.5（缩放类损伤，`READ_TUNE.phaseReliable`）：弃用相位、退回幅度重建（PGHI + RTISI-LA）。
- < 0.5 但 ≥ 0.3 且**票根证明图未缩放**（`READ_TUNE.phaseReliableJpeg`）：保留相位；
  纯 JPEG 色度损伤把比值压到 ~0.34，方向仍在，保留大幅优于弃用（实测相关 0.65 vs 0.08）。

带 meta 的可逆图被**等比缩放**时走条码票根通道恢复几何（见上节），不再使用
「竖向压缩行数 + 时长不变重推」的旧路径（等比缩放下帧数会推错数倍）。

## meta 防篡改

tEXt 解出的字段除 ref（一位小数）外必须全为整数：帧数/频点数带小数会让逆变换
产出全 NaN 音频，宁可拒认、走上面的几何兜底。
