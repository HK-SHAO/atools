# 算法原理与实测结论

格式契约（像素布局、元数据、票根位流）见 `format-spec.md`，本文只讲 DSP 与实测。

## 编码

- Hann 窗 STFT；`hop ≤ win/2`（Hann + WOLA 下超半窗会窗缝漏能量，出周期性哒哒声）
- 幅度：dB 线性映射到 0..255（可逆模式 0..65535），动态范围 = 12×位深 dB，自动覆盖
- 相位存 **cos/sin** 而非折叠角：在 2π 处连续，有损重编码只平滑漂移、不产生 2π 跳变的爆尖刺

## 重建三路径（synthesise）

| 输入 | 路径 |
| --- | --- |
| 相位完好（可逆图） | 直接逆 STFT。相位是最优估计，任何迭代只会更差 |
| 无/弱相位 · fast | PGHI 相位初始化（γ=0.25645，单相 RTISI 一次成型）→ RTISI-LA 逐帧反演（8 迭代 + 前瞻） |
| 无/弱相位 · 精修 | RTISI-LA 16 迭代 + 更大前瞻预算 + 锚定 GL（8 轮 / 12s 预算） |

RTISI-LA 逐帧推进 + 前瞻共识反转，是零爆音的关键；GL 打磨收敛谱残差但改变波形对齐。

**锚定 GL**：GL 每轮幅度投影后，向「存储幅度 × 参考相位」做逐 bin 凸混合 `S ← (1−λw)·投影 + λw·锚`，w = 读端测的逐 bin 相位置信度（圆矢量长度），λ=0.85，动量 0.99。等价于最小化 `‖|STFT x|−A‖² + λΣw·(1−cos∠(x,φ_ref))` 的交替下降，参考相位是每轮都参与的先验锚，不只当初值（只当初值会被迭代漂移掉；参见 Phase Inpainting in Time-Frequency Plane, Krémé et al. 2018）。

## 实测（合成示例音 44.1kHz / 3.2s，还原度 = 与原波形相关）

| 场景 | fast | fine | fine·预算×4 | 相位完好直逆 |
| --- | --- | --- | --- | --- |
| 紧凑 8bit | 0.611 / LSD 3.48 | 0.597 / 3.08 | 0.590 / 2.70 | 1.000 / 0.60 |
| 相位被弃（模拟缩放） | 0.517 / 3.46 | 0.502 / 3.12 | 0.440 / 2.76 | 同上 |

结论（勿再"优化"回去）：

1. **无锚定时精修只降谱失真（LSD −0.4~−0.8），不提升波形还原度**（持平或略降），GL 拟合谱的同时推离原波形。
2. **加大迭代预算收益递减且开始劣化**，现参数已在这套启发式的饱和点。
3. **相位信息缺失是信息论天花板**：0.4~0.6 的相关与迭代量无关。有损容器不丢这个信息（JPEG 后保留相位仍 0.65 vs 弃用 0.08），缩放才抹掉它。

## 相位可靠性分级（读端）

「平均矢量长度比」：1:1 图 ≈1.00，JPEG q0.72 ≈0.63（色度下采样平均掉一半矢量，方向仍在），缩放 0.5× ≈0.3-0.4（矢量抵消，信息已毁）。三档：≥0.5 作真值直逆；≥0.3（未缩放）或 ≥0.15（缩放 <0.6× 内）作**弱锚**保留，默认加载走幅度重建，「重建相位」按钮用锚定 GL；低于下限弃用。

弱锚实测（全语料基准：docs 下 43 段音频各取前 8 秒，含语音、游戏语音、音乐；相关 = 与原波形对齐相关，fast 为默认档）：

| 损伤 | fast | fine（锚定） |
| --- | --- | --- |
| JPEG（1:1） | 0.633 | 0.670 |
| 缩放 0.9× | 0.117 | 0.208 |
| 缩放 0.75× | 0.141 | 0.389 |
| 缩放 0.75×+JPEG | — | 0.243 |
| 缩放 0.5× | 0.093 | 0.093（相位已弃，无锚） |

关键分野：**JPEG 损伤近似随机，迭代能纠；缩放混合的相位损伤是系统性的（方向有偏），迭代会锁死偏差**。故 0.5× 缩放不锚（门限 0.6×），0.75× 仍净收益。

消融记录（子集 12 段 × 4 损伤场景，fine 档）：

1. **λ 单调**：0.85 ≥ 0.5 > 0 在全部损伤场景、全部音频组成立，无一处反例；λ=0 时 JPEG 场景反而从 0.649 掉到 0.185（锚定同时充当正则与先验）。
2. **GL 动量 0.99**（FGLA 实践值，Perraudin et al. 2013）：全场景小幅提升（s75 +0.009、s90 +0.016、jpeg75 +0.024），0.9 已获大部分收益，0.95 饱和。已设为默认（原 0.5）。
3. **无效变体，勿再试**：λ 退火（中性略负）；幅度门控（锚权乘幅度比，显著变差 0.649→0.451，低幅度 bin 被压掉后锚太弱）；RTISI 暖启动混入参考相位（对最终质量零影响，锚定 GL 收敛到同一终点）。
4. **小型判别式网络修正相位（负结果，2026-09 实验）**：用真实管线转储 15 文件 × 5 损伤的训练对（`bench/ml/train.py`，torch CPU），训 12.5k 参数 patch CNN（7/9/15 感受野、加时间频率绝对位置通道、残差式输出）从损伤相位+幅度预测干净相位。逐 bin 加权圆误差确实降（val：jpeg 56→54°、s90 93→84°、s75 99→91°），但接进锚定 GL 后端到端**显著变差**（12 文件×4 损伤：s75 −0.168、jpeg75 −0.108、合并 −0.070，负回归 32/48）。根因：局部 patch 的逐 bin 修正在空间上不一致，不是合法的 STFT 相位场，替换锚后 GL 锁死在错误先验；原始损伤相位虽噪但保留了真实结构。要真正从 DL 获益需 DeGLI 式（网络嵌进 GL 迭代内、每步一致性投影、全局感受野，0.1-2M 参数）或神经声码器（13M 参数起、语音域、泛化差），体积与零依赖定位冲突。复跑入口：`DATA='["jpeg","s75"]' bun run bench` 转储 + `bench/ml/train.py` + `NEURAL=weights.json bun run bench`。

## 解码链路与覆盖面

原生 `decodeAudioData` 各家支持参差（Safari 不认 OGG、部分安卓 WebView 不认 ALAC 等），
故一律「原生优先、失败按嗅探落 WASM 引擎」。Ogg 容器无可靠嗅探特征时按**首包魔数**定序
（Opus 头 / Vorbis 头），同一容器里的另一种编码留作次选兜底 —— 见 `audio.ts` 的 `FALLBACKS`。

**Bun 没有 Web Audio**：`window.AudioContext` 不存在，`decodeNative` 恒返回 `null`。
于是 `bun test` 里每个解码夹具都只走到 WASM 兜底引擎，**等价于「最坏浏览器」（原生全拒）下的链路**。
原生成功路径、以及「原生失败 → 落到正确引擎」这段切换，测试覆盖不到，只由评测台
（`bun bench/run.ts`）在真实浏览器里端到端覆盖 —— 动解码链时这一条要跑评测台，别只看单测。

## 数值层的等价性边界（消融结论）

一轮数值优化之后逐处消融（`bench/` 下的临时台架在「优化前」`8a55099` 与「优化后」两棵源码树上跑同一套
矩阵，再逐字段比对）。**先说结论：哪些是严格等价，哪些只是统计上无差别。**

| 改动 | 等价性 | 证据 |
| --- | --- | --- |
| `coverage` 抽取到 `fft.ts` | 逐位相同 | 先把 `w[m]*w[m]` 提到循环外存成表，加法顺序一字未改 |
| `synthesiseExact` 位循环把 `re`/`im` 提出 `Math.sqrt` | 逐位相同 | 纯 CSE |
| 重采样相位表（含回退分支） | 逐位相同 | 2859 组矩阵逐样点比位，最差 0 个样点不同 |
| `Math.pow(10, d/20)` → `Math.exp(d·ln10/20)` | **不是逐位相同**，差 ≤32 ulp | 96.5 万个取值：90.3% 逐位不同，最大 32 ulp（相对 ~7e-15） |
| RTISI 相位由 `atan2` 角改存单位相量 | **不是逐位相同**，差 ~1e-15 | 同输入两版输出相对 RMS 1e-14（细档）～ 1e-1（粗档，见下） |
| 精确档编码的相位由 `cos/sin(atan2)` 改为 `re/h`、`im/h` | 逐位相同 | 9 档配置共 1,284,612 个相位字节 0 处不同 |

「IEEE 舍入相同」这个说法当时写得太满，实测不成立 —— `d/20` 与 `d·(ln10/20)` 各自要先舍入一次，
之后 `pow` 与 `exp` 又各走各的实现。**但量级是 1e-15，远在 Float32 精度（6e-8）之下**，所以
exact 档的指标在 32 组素材上**一格不差**（Δ 恒为 0，96/96）。

### PGHI 只认顺序，不认数值

PGHI 的相位传播由 `orderByLevel` 的幅度分桶顺序决定，于是它对输入的敏感性是**离散的**：

- 把整条 `target` 逐元素乘 `1 ± 1ulp`（非单调摄动）→ 相位摆动 12%~95%，最大到 360°；
- `pow → exp` 改了 90% 的 `target` 数值（最大 32 ulp），相位却**逐位一个都没变**。

因为 `pow` 与 `exp` 都是 `db` 的**单调**函数：数值变了，但任意两个 bin 之间的大小关系、
以及「量化到同一档因而严格相等」的并列关系都完整保留，分桶顺序因此纹丝不动。
**推论：动 `targetOf` 的算法只要是单调改写，就不会碰相位；一旦改成非单调（哪怕只差 1 ulp），
相位会大范围翻掉。** 这是改这一层时唯一要守的界线。

### RTISI 在 hop = win/4 的粗档是病态的

细档（win 1024 / hop 256）稳如磐石：同输入两版 RTISI 输出相对 RMS 1e-12~1e-15。
粗档（win 256 或 512 / hop 128）**对 1 ulp 的输入摄动会被放大到 ~10% 的波形变化** ——
`mag` 只差 1 ulp，或相位表示从 `atan2` 换成单位相量，输出相对 RMS 都是 1e-1。

这是算法本身的条件数（K = R−1 只有 1 或 3，迭代次数 8），不是本轮改出来的：把「旧 RTISI 配旧 pow
幅度」与「新 RTISI 配新 exp 幅度」相比同样差 1e-1，两者的差异都落在同一量级。

单一组素材上比指标因此没有意义，改比**分布**：32 组种子 × 3 类素材 × 11 个用例，配对比较 4 项指标
（相关 / SNR / LSD / 收敛），**没有任何一组达到 p < 0.01**，符号计数普遍在 13/19 ~ 19/13 之间摆动，
即粗档换了个等价的解，不是变好也不是变坏。exact 档与细档则连数值都锁死（Δ ≈ 0）。

**纪律：再动这一层，必须按分布比，不能拿单条素材的指标升降当结论。**

## 重采样与主线程预算

重采样的抽头权重只由输出相位 `frac = frac(j·from/to)` 决定，取值个数等于采样率比既约后的分母
（44.1k→8k 是 80）。原实现每个输出样点都把 `sin`/`cos` 现算一遍：44.1k→8k 是 48 抽头 × 48 万
输出点 = 2300 万次超越函数。改成同一相只算一次存表，其余查表。

表以 `frac` 本身为键、值与原处逐位相同，所以**输出逐位不变**（`spectrum.test.ts` 有比位用例钉着），
音质门禁不会因此漂。上限**同时按条数与内存双重封顶**：`min(1<<14, 4 MB / (2·half·8))`，最坏 4 MB。

上限不能只按条数设小 —— 同一个相会因浮点漂移散成近十种 `frac`，实测算下来的**相位数**是：

| 组合 | 既约分母 | 实测相位数 |
| --- | --- | --- |
| 44.1k→8k | 80 | 721 |
| 44.1k→32k | 320 | 2884 |
| 11.025k→16k | 640 | 5001 |
| 22.05k→32k | 640 | 5385 |
| 11.025k→32k | 1280 | 10001 |

11.025k / 22.05k 是正经的源采样率，16k / 32k 是界面上真有的目标档，所以**这些组合不是构造出来的**。
上限若停在 4096，它们会顶穿上限，而顶穿之后每个样点都是「Map 未命中 + 现算 + 重新分配一个数组」，
比逐样点现算**还慢 1.18×**（11.025k→32k 实测 159.6 ms 对 135.6 ms）——这是本轮唯一一处真回归。

修法两条，缺一不可：**（一）上限按内存放到 1<<14，把所有真实组合装下；（二）真顶穿了就整段
退回现算，且回退路径不再分配数组**，于是最坏只与逐样点持平，永远不可能更慢。
两条分支的等价性是分开证的：正常跑一遍 2859 组矩阵，再把 `memo` 强制为 `false` 全程走回退跑一遍，
两遍的输出逐位相同（`bun bench/perf.ts` 另有一条比值门禁盯着，退化到 1.05× 以下即不合格）。

60 秒单声道实测（`bun run perf`）：

| 组合 | 相位表 | 逐样点现算 | 倍数 |
| --- | --- | --- | --- |
| 44.1k→8k | 30.2 ms | 192.9 ms | 6.4× |
| 44.1k→16k | 28.2 ms | 198.4 ms | 7.0× |
| 44.1k→48k | 37.9 ms | 204.7 ms | 5.4× |
| 11.025k→16k | 14.9 ms | 67.5 ms | 4.5× |
| 11.025k→32k | 32.2 ms | 135.6 ms | 4.2× |
| 22.05k→32k | 30.3 ms | 133.7 ms | 4.4× |

真实页面里同样落一个 60 秒 44.1k WAV（默认 8k 紧凑）：主线程长任务从 551 ms 降到 193 ms，
其中 64 ms 还是测量脚本自己合成 WAV 的开销；余下落在解码（原生 `decodeAudioData` 加合轨）上，
`silenceBounds` 只占 3.7 ms。

**结论：这条链上不值当引 Web Worker。** 唯一的常驻毛刺是块头大、次数少的一次解码，
而原生 `decodeAudioData` 在 worker 里根本不可用。真正有 worker 形状的是 WASM 兜底解码
（见上节：整曲能跑几分钟），但那要先把「原生 / WASM」两条路拆开，且现实中它主要接 AMR 这类
短语音；等页面上真的出现长文件卡死，第一个该搬进 worker 的就是它。

## 内层还剩多少余量（2026-09 复检）

按「缓存 / 访存 / 分帧 / 时域迭代 / 惰性处理」逐项复检了一遍，
**结论是这条链上已经几乎没有实现余量，剩下的开销是算法本身的**。
先把各阶段归属摆出来（30 秒单声道；`targetOf` 与 `coverage` 未导出，是就地复刻的等价循环，只为量量级）：

| 档位 | frames×bins | encode | targetOf | PGHI | RTISI | coverage | synthesise |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 8k 紧凑 中 | 938×257 | 12.9 | 0.7 | 22.4 | 132.9 | 0.4 | 169.8 |
| 16k 紧凑 中 | 1876×257 | 20.1 | 1.4 | 28.8 | 122.1 | 0.7 | 169.2 |
| 8k 紧凑 细 | 938×513 | 20.1 | 1.2 | 26.7 | 142.6 | 0.6 | 175.1 |
| 8k 精确 细 | 938×513 | 72.5 | 1.3 | 31.2 | 143.4 | 0.7 | 21.1（走 `synthesiseExact`） |

（单位 ms。）**RTISI 一个占掉七成以上**，而 `targetOf` 与 `coverage` 都不到 1.5 ms。
所以下面这些都是**量过之后否掉的**，不是没想到：

| 念头 | 实测 / 预估 | 为什么不做 |
| --- | --- | --- |
| `targetOf` 按 256 档 level 建幅度表 | 全量只有 0.7~1.4 ms | 省不到 1 ms，多一张表不值 |
| `coverage` 从 O(frames·win) 改成 O(padded·win/hop) | 0.4~0.7 ms | 同上；每次合成只调一次 |
| `hannWindow` 建表缓存 | ≈0.1 ms | 量不出来 |
| `encode` 把峰值扫描与主循环合并 | 省 240 次 FFT ≈ 1.3 ms，代价是 4 MB 中间缓冲 | 净收益 ≈ 0 |
| PGHI 的 max-heap 换分桶队列 | 快 1.73×，但 `fine` 相关从 1.0054 掉到 0.9729 | 见「PGHI 只认顺序」——顺序一乱相位就翻，是碰运气不是改进 |
| RTISI 的复数 FFT 换实数 FFT（实入 / 对称出各砍一半） | 预计省 ~50 ms | **不是逐位等价**，而粗档 RTISI 是病态的（1 ulp → 10%），要重跑整套统计才有资格说没退化；收益与代价不成比例 |
| `Int8Array` 存 `phaseSin` | 省 2×660 KB | 每元素多一层算术，访存没到瓶颈 |
| 把解码或 `resample` 搬进 Web Worker | — | 见下节结论 |

相位表、FFT 旋转因子表这些**能缓存的地方已经缓存了**；剩下的 `RTISI` 开销按 `frames × (1+iters) × act`
次 FFT 计，是迭代结构与 FFT 次数决定的，不是内层写法决定的。

### 精确档的相位：`atan2` + `cos` + `sin` → 单位相量

`phaseCos`/`phaseSin` 存的就是单位相量，而算 `db` 那一步本来就求了 `h = √(re²+im²)`。
所以 `cos(atan2(im, re))`、`sin(atan2(im, re))` 可以直接换成 `re/h`、`im/h`，一个 bin 少三次超越函数。
内层实测 **2.12×**（513 bin × 1000 轮：9.9 ms → 4.7 ms）。

等价性按**字节**验：9 档配置（8k/16k/44.1k × 三档 fineness × 两档 fmax）跑下来，
**1,284,612 个相位字节 0 处不同**，`levels` 也 0 处不同。
`spectrum.test.ts` 有一条用例拿 `atan2` 参照实现逐字节钉着它。
（`h = 0` 时原式给 `cos=1`、`sin=0`，改写后显式填 255 / 128，两者一致。）

### `synthesiseExact` 的上半谱必须清零

`Frames.add` 做的是**全长**的 Hermite 反变换，所以「写满 `bins`」等于「写满整个上半谱」
这件事只成立于 `bins === win/2+1`。`encode` 恒满足（全频段时 `rowsFor` 就返回 `win/2+1`），
但 image 侧的 `winFromBins` 有 256 的硬下限：幅度带短于 129 行时 `win` 被顶在 256，
于是 `bins < win/2+1` —— 一张被缩到 258 px 以下的票根图正好落进这一段。
不清零的话，上一帧反变换出来的时域样本会被当成本帧的谱线再变一次。

实测：`bins = win/2+1 = 257` 时清不清零**逐位相同**（那行是空转）；
`bins = 129` 时同一条谱的峰值差 **3.6%**。所以这行是零成本的兜底，
把「`bins` 必须等于 `win/2+1`」这条横跨两个文件的隐式前提从 `synthesiseExact` 里摘掉了。
